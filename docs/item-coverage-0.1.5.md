# 0.1.5 アイテム入口とデータ成分の監査

対象はMinecraft 1.21.1 / NeoForge、Immersive Engineering 12.4.2-194です。固定した配布JARのSHA-256は `45942985a4a4aebf265b8e22a0c54a96208637471f36f2532ff5d4911322debc` です。依存JAR・画像・模型・構造・手引書本文は、このガイドへ同梱しません。

## 原因と修正

0.1.4（`bfee6be`）では、Wの58 IDとShiftの9 IDを合わせても64 IDだけでした。代表的な模型の部品登録と、短文説明5組では、手引書が扱う道具・機能・色違いを十分に拾えていませんでした。また、Ponder 1.0.87のItemStackファクトリーはアイテムIDだけで場面をコンパイルし、入力スタックのデータ成分を保持しません。

今回のW対象は69 ID、Shift対象は568 ID、和集合は625 IDです。Wには模型で使うMinecraftのホッパー・ピストン・大釜の3 IDを含みます。既存20教材・140ステップ・章順・字幕・要約・模型配置は維持し、内容が合う完成機械11 IDだけを既存の組立教材へ追加しました。その他の機械・道具・素材・建材には、役割・入力・条件・注意点を短く伝える119組の説明を追加しています。全124組の説明は22言語です。

完成機械のアイテムは、そのまま置いて完成する装置として説明しません。残る機械のShift説明は役割と操作条件の導入で、すべての組立手順を新しいPonderにしたものではありません。元の手引書があること自体を入口漏れの除外理由にもしていません。

Wから開く実スタックを防御的にコピーし、このガイドの対応する場面のアイテム表示へ引き継ぎます。カバー付きコンベアの `immersiveengineering:default_cover` などを消去しません。標準カテゴリーから別教材へ進んで戻った場合も保持します。データ成分が異なる自ガイドの履歴を区別し、他ガイドの場面・コンテキスト・履歴判定は既存の所有確認を保ちます。通常画面へ独自ボタンは追加しません。

## 登録から独立した期待集合

`tools/extract_manual_inventory.py` は対象JARだけを読み、ガイドの登録表・翻訳・件数を参照しません。再帰的な `baseRecipe`、手引書のアイテム表示、位置指定レシピ、レシピ出力、液体の容器を別々の根拠として保持します。原料の文字列をすべてレシピ出力として数える方式ではありません。

- 手引書113 JSON、関連付け478件、IEのユニークIDは408件です。実際のレシピ出力リンク341 IDと、表示のみ67 IDを区別します。
- この408 IDのうち、変更前に両入口がなかった352 IDは、変更後すべてWまたはShiftへ接続しています。IDごとの元リソース・変更前後の入口は [機械可読監査](item-coverage-0.1.5.json) にあります。
- 実レシピの出力から20の派生形群を取り出し、実装が登録するシェーダー・袋の群を加えた21群を照合します。色付きシュートを含む20種類のシュート、18種類の金属足場、54種類の板金の材質・色・形状などを含みます。
- カバー付きベルトは架空の別IDを作らず、既存ベルト5種類のレシピ成分を保持します。4種類は既存W、分配型は対応するShift説明です。設計図5種類、照明弾3種類、効果の異なるポーション容器2種類を含め、15の実スタックfixtureを用意しました。
- ストリップカーテンとイヤーマフは、それぞれ実際の16色の染料成分を使って確認します。機能が同じ色違いに、無関係な場面や空の教材は追加しません。

配布JARの691個の直接アイテムモデルは、実レジストリの件数として扱いません。テンプレート・トリム・内部表示用モデルを含むためです。実クライアントの全IEアイテムからW・Shift・根拠付き除外を照合し、不明な残りがある場合は検証を失敗させます。

対象外は20 IDを明示しました。通常の防具・工具と同じ基本動作を使う鋼鉄装備9 ID、管理・クリエイティブ用の敵スポーンエッグ3 ID、内部表示用アイコン8 IDです。理由と固定版の実装根拠は [期待集合](item-coverage-expectations.json) にあります。機能が未実装という理由で対象外へ移していません。

固定版の手引書には古い参照が6件あり、未解決のレシピ・名称として監査へ残しています。存在しないIDを新しい登録として捏造しません。保存したソースアーカイブには12.4.3の版表示があるため、12.4.2の仕様根拠には固定配布JARとそのバイトコードを優先しました。

無限キャパシタは対象外から外しました。固定版ではIEの通常クリエイティブタブに現れ、無限に電力を供給します。初期の全6面は出力ですが、ハンマーで面を切り替えられ、送電は出力面だけです。本体のアイテム説明は名前と任意の蓄電数値だけで、この機能説明はありません。独立したShift説明を追加し、有限キャパシタのW教材へは混ぜません。[固定版の実装・nativeツールチップ監査](creative-capacitor-0.1.5.md) を参照してください。

## 内容・翻訳・検証範囲

条件の校正では、Faraday装備の低出力防護と高出力Teslaの被害増加、照明・砲塔の電力と標準レッドストーン制御、刃なしの皮むきと刃付きの原木から板材への切断、液体へ固体を混ぜるミキサー、鉛入りコンクリートの完全ブロックだけのテレポート抑制、スニークで開閉するはしごを確認しました。各言語の単位ごとに通常・警告・助言を作者が指定しています。

新しい119説明の全20翻訳と日英原文を意味としてレビューし、既存説明の長い13キーもDE/HI/ID/MS/VI/PL/ROで完結した短文へ推敲しました。英語名と明示した翻訳案を保持し、幅だけで文を途中から別単位へ送っていません。母語話者による翻訳認証は主張しません。

実フォントは全124説明・22言語を対象とします。ツールチップの論理順文字列を保ち、Minecraftが実際に描く `Component.getVisualOrderText()` の字形と幅で折り返しを確認します。アラビア語を事前整形したComponentとして渡す二重整形はしません。超過・欠落は全言語を調べてからまとめて失敗させます。

実施結果・配布物のハッシュ・Prismへの配置は [検証記録](verification.md) と [今回の成功JSON](validation-0.1.5.json) を参照してください。未変更の7,936字幕単位の実フォント証拠は0.1.4を利用し、全シーン・全字幕の高額な再測定は行いません。Wは標準公開ファクトリー・標準ヒントと実画面遷移、Shiftは実ツールチップ追加経路の展開前後を検証します。物理キーの押下、任意のユーザー成分の全組合せ、Prismの全MODでの同時起動、別版・別ローダー、サーバー接続は今回の対象外です。

## 再検査

```powershell
python tools/test_item_coverage.py
python tools/check_item_coverage.py --ie-jar build/research/ImmersiveEngineering-1.21.1-12.4.2-194.jar
.\gradlew.bat compileJava generateGuideResources build compileValidationJava
.\tools\run-validation.ps1 -Coverage -LogPath build/item-coverage-validation.log
python tools/check_item_coverage.py --ie-jar build/research/ImmersiveEngineering-1.21.1-12.4.2-194.jar --runtime-result docs/validation-0.1.5.json --release-jar build/libs/immersive-engineering-ponder-guide-0.1.5-neoforge-1.21.1.jar --report docs/item-coverage-0.1.5.json
```

最後のコマンドは、成功JSON・固定期待集合・実行した検証クラス・配布JARの各ハッシュと実登録を照合して、静的監査へ実行結果を結び付けます。古い結果や異なるJARでは成功しません。検証用クラスは配布物に入りません。
