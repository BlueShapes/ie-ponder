# Content translation coverage

The guide has 185 content keys: 20 lesson titles, 20 summaries, 140 authored subtitles, and five short item descriptions. Together with 16 navigation keys, every supported locale contains 201 generated entries.

Japanese and English originals remain in the canonical guide JSON files. The other twenty languages are authored separately in `src/main/translations/content/<locale>.json`. English fallback is reserved for missing or unsupported locales; English paragraph copies are rejected in translated content.

As of 0.1.4, narration explains operations, mechanisms, states and conditions/results naturally in all 22 locales. Ordinary assembly steps describe the structure and the effects of tools; purposeful diagnostic checks, safety requests and remedies remain. This is a per-locale semantic rewrite, not a bulk ending replacement or an imperative-count target. Summaries, item descriptions and chapter descriptions are included. Existing official names and proposed-name labels, recipe caveats, quantities and operation targets remain part of the review. See [narration review](narration-0.1.4.md).

The authoring/review groups covered German, Spanish, French, Italian, Brazilian Portuguese, European Portuguese, Czech and Russian; simplified Chinese, Taiwan Chinese, Hong Kong Chinese, Hindi, Korean, Vietnamese and Turkish; and Arabic, Indonesian, Malay, Polish and Romanian. All groups considered the Japanese terminology corrections against the installed IE 12.4.2-194 JAR while preserving the English source facts.

Official item and fluid names were checked against that exact dependency. Unavailable current item-name translations retain the English identifier and an explicitly proposed local name. Legacy translation keys are distinguished from names actually selected by the current resource stack. Region-specific Chinese and Portuguese wording was reviewed separately; Czech uses polite plural instructions and European Portuguese uses `tu`. Arabic source is logical-order Unicode.

`content-review.json` records the canonical Japanese/English source fingerprint and each reviewed translated file's SHA-256. Changing either original requires review of affected translations; changing a translation invalidates its recorded hash. `tools/check_translations.py` and resource generation check coverage, nonempty values, placeholders and review freshness. The worker's supplementary Asia review note documents terminology decisions without asserting a fabricated source hash.

Caption strings use explicit newlines between authored display units. Each unit is normally one concise, grammatically complete sentence. Language-specific rewriting preserves conditions, quantities, target identity, causality and order. Long material lists become several complete instructions. Units are never sliced by font width, line count or word count, and separate sentences are not combined just because they fit.

As of 0.1.3, own captions, summaries, descriptions and chapter prose omit ordinary sentence-final full stops in all 22 locales. Decimal/version/ID/abbreviation dots and paired continuation ellipses remain meaningful source text. The punctuation migration is checked against the previous revision for unchanged wording and unit order; it does not retranslate the existing lessons. Multi-sentence item descriptions now retain explicit newline boundaries. A final full stop is not required for a grammatically complete authored unit; fragment, multiple-sentence and continuation checks remain active.

`text_tones.json` explicitly assigns NORMAL, WARNING or HINT to each caption and description unit in each locale. Locale-specific boundaries receive their own arrays, never an English index fallback. Normal text uses native WHITE, warnings RED and advice GREEN; native Ponder lightens these body colors. Tooltip descriptions use the same light colors. Scene outline palettes are independent. Resource generation and `tools/check_text_tones.py` check every key, unit count and enum value.

For an unavoidable continuation, the author defines natural clauses with a suffix `…` on the preceding unit and prefix `…` on the following unit. Intermediate units in a longer chain have both. Newlines define the boundaries; ellipses occurring inside ordinary prose do not create boundaries. The paired marks do not omit content. Normal short sentences need no continuation marks. Structural checks reject orphan/mismatched marks, missing endings, unmarked fragments and multiple sentences inside one authored unit; semantic review is still required.

`CaptionUnits` is independent of Minecraft and has dependency-free regression tests. Its fallback for text without authored newlines recognizes sentence punctuation while protecting abbreviations, decimals, version numbers and registry IDs. Ambiguous or oversized input stays intact. `tools/check_captions.py` runs the actual parser against all 3,080 localized captions before a client launch. The width argument cannot change any unit boundary.

Native captions wrap naturally inside each bubble at 180 pixels. A guide-owned native `TextWindowElement` subclass recomputes its point through Ponder's public scene transform and near-target layout, preserving that width after resizing to a 320×240 GUI. The standard renderer, border, fade and font remain unchanged. Font verification rejects complete units above three lines and reports every offending locale/key together; it never resolves overflow by creating fragments. Each unit receives its own reading time, with the authored step's keyframe, outlines and sequential ingredient controls retained. Arabic lines are measured after shaping while source/search text remains logical and is shaped only once by the native draw path.

Runtime checks and their actual outcomes are recorded in [verification](verification.md). Source checks alone do not prove rendering, and these translations have not been certified by native-language editors.

The opt-in client exports its measured glyph advances to `build/validation-run/caption-font-metrics.json`. `tools/check_caption_widths.py` uses those advances only as a cheap draft aid. It reports unmeasured glyphs and defers Arabic contextual shaping to Minecraft. A sibling project's cache is not proof of an identical font stack. Changed wording still receives the actual Minecraft wrapping/shaping check; cached widths never create authored boundaries or truncate text.

## Native Ponder controls

The Ponder dependency does not provide every supported locale's native guide controls. The separate `native-ui` sources supplement 145 missing/untranslated or invalid-placeholder labels, including complete native guide controls for Hindi, Hong Kong Chinese, European Portuguese, Malay and Arabic. Other complete upstream translations remain in the dependency. Russian's empty supplement records that no override is needed.

The 22-string English source reference comes from Ponder 1.0.87 under its MIT license. Generation verifies that reference against the actual dependency JAR, checks required supplement keys, hashes and placeholders, and writes only ordinary language JSON. The two upstream category labels that omitted the mod-name placeholder (Spanish) or hardcoded Create (Korean) receive corrected placeholders.

These library-owned translation keys necessarily live in the native `ponder` language resource path. Guide IDs, commands, progress and Java/mixin identifiers remain scoped to `ieponder`. This uses Minecraft's resource merging, with no global Ponder text redirect, asset copying or custom screen. Runtime checks read the composed active language, including native UI labels and their font glyphs.
